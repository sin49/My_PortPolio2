## [핵심 1] AI의 예측을 측정으로 검증한 최적화

**문제**: 적이 수천 마리가 되면 충돌 판정이 "모든 적 × 모든 적" 비교라 급격히 느려짐 (6,000마리 25 FPS).

**한 일**
- 맵을 격자로 나눠 근처 후보만 검색하는 **Spatial Hash를 의사코드를 보고 직접 구현**
- 전체 순회와 해시를 같은 인터페이스로 감싸서, 실행 중 전환·결과 동일성 테스트가 가능하게 함 (AI 설계)
- 적 수를 자동으로 늘리며 측정해 CSV로 저장하는 벤치마크로 같은 조건 전/후 비교 (도구는 AI 작성, 첫 기준선은 직접 측정)

**결과**: 6,000마리 기준 로직 7.04 → 3.02 ms (2.3배), 렌더 개선까지 합쳐 25 → 60 FPS, 최대 9,900마리 58.7 FPS

**포인트**: 구현 전 AI는 "로직 5~8배 향상"을 예측 → 실제는 2.3~2.6배. 그대로 넘어가지 않고 칸 크기 실험을 요청해, 적이 한 자리에 수백 마리 겹쳐 있어 칸을 나눠도 비교 대상이 줄지 않는 것이 원인임을 확인.

이미지: `chart_perf.svg`

## [핵심 2] 세대 번호 핸들로 엔티티 수명 관리

**문제**: 적을 포인터로 들고 있으면, 적이 죽고 그 자리에 새 적이 생겼을 때 모르고 접근하는 버그가 생김. 순회 중 삭제도 위험.

**한 일 (의사코드를 보고 직접 구현)**
- 고정 슬롯 풀(9,999칸, 주소 고정) + `Handle{칸 번호, 세대}`
- 칸이 비워질 때 세대 +1 → 옛 핸들은 자동으로 무효(`Get()`이 nullptr)
- 삭제는 예약만 하고 틱 끝에 일괄 처리 → 순회 중 삭제 없음

이미지: `diagram_handle.svg`

## [핵심 3] 이전 프로젝트의 문제를 명시적 FSM으로 개선

**문제 (이전 Unity 팀 프로젝트 "배터리")**: 적 클래스의 상태가 bool 7개와 코루틴에 흩어져 있고, 싱글톤을 직접 참조하며 한 파일이 973줄.

**한 일 (근접 적 AI, 의사코드를 보고 직접 구현)**
- `enum class` 상태 + 상태 진입 시 타이머 설정 + 매 틱 현재 상태의 일만 → 코루틴 없음
- AI는 "의도"만 기록하고 이동·판정은 다른 시스템이 처리

**결과**: 근접 적 AI 100줄. 같은 틀로 원거리 적·2페이즈 보스까지 확장. 공격 예고 범위 표시도 AI 코드 수정 없이 렌더에서 상태를 읽어 붙임.

이미지: `diagram_fsm.svg`, (보조) `diagram_tick.svg`

## [과정] AI 협업 방식

- 기능마다 **의사코드 먼저 합의** (Claude 작성 → Codex 교차 검수) → 구현 → 빌드·테스트 → **직접 플레이 확인** → 커밋
- 작성자를 파일 이름(`_U` 본인 / `_C` AI)과 개발 기록에 구분해서 남김
- 개발 기록(devlog)에 "AI 제안 / 내가 고치거나 거절한 것과 이유"를 날짜별로 기록

| 사례 | 내용 |
|---|---|
| 제안 거절 | "누르는 순간 대시" 제안 → 원래 의도(짧게 = 대시 / 길게 = 달리기)와 달라 거절 |
| 교차 검수 | Codex 리뷰가 내 코드에서 테스트로 못 잡던 버그 2건 발견 → 원인 이해 후 반영 |
| 플레이 검증 | 적이 발판에서 바로 뛰어내려 발판이 의미 없다는 문제를 플레이로 발견 → 수정 요청 |
| AI 실수 | AI가 빌드 설정 파일 인코딩을 깨뜨림 → 복구, 기록에 남김 |

## [정리] 배운 점 · 한계 · 다음 단계

- **배운 점**: AI를 쓰는 것만큼 결과를 수치와 실제 동작으로 확인하는 것이 중요. 예측이 빗나간 지점에서 원인을 찾는 과정이 가장 많이 배운 부분.
- **한계**: 코드 대부분은 AI 작성 (직접 구현은 World, Spatial Hash, 근접 적 AI, Stats). 그래픽 리소스 미적용. 성능 수치는 인위적인 스트레스 테스트 기준.
- **다음 단계**: 겹친 적 처리(진영별 검색 분리 + 적끼리 밀어내기), 리소스·플레이 영상 보강, 살아 있는 칸만 도는 순회와 중복 제거 개선.

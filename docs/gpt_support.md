# Codex / GPT 보조 검토 및 인수인계

> 사용자 합의: 2026-11-17. 기본 담당은 Claude(주 개발), Codex(리뷰·조언·학습 보조), 사용자(최종 결정·World 직접 구현).

## 1. 기본 역할과 수정 권한

- Codex는 코드 리뷰, 설계 검토, C++ 설명, 사용자 구현 보조를 맡는다.
- **평상시 Codex가 생성·수정할 수 있는 프로젝트 파일은 이 문서(`docs/gpt_support.md`)뿐이다.** 소스, 테스트, CMake, 다른 문서의 수정·이름 변경은 하지 않는다.
- 관련 파일 조회 및 검증은 가능하다. 빌드·테스트는 생성물만 갱신하는 범위에서 수행하고, 실행 여부와 결과를 구분하여 보고한다.
- 발견한 문제는 위치·원인·영향·수정 방향을 제시한다. 실제 수정은 사용자 또는 Claude가 수행한다.
- 사용자가 직접 구현하기로 한 World는 대신 작성하지 않는다. 완성 코드보다 힌트와 짧은 문법 예시를 우선한다.
- 커밋은 사용자가 직접 한다. Claude와 같은 파일을 동시에 수정하지 않는다.

## 2. Claude 업무 대행

Claude 사용량 부족 등으로 **사용자가 대행을 명시적으로 요청하면**, 요청 범위에 한해 구현 업무를 인계받는다. 사용량 부족을 추측하여 스스로 전환하지 않는다.

대행 시작 시 Git 변경 내역, 관련 설계, 실제 구현을 확인하여 완료·미완료와 사용자 작성 부분을 구분한다. 새 기능은 의사코드 합의 절차를 따른다. 대행 중에도 사용자 직접 구현 범위는 별도 위임 없이 대신 작성하지 않는다.

대행 종료 시 이 문서에 아래 내용을 남겨 Claude가 이어받도록 한다.

- 대행 요청과 범위
- 변경 파일과 변경 이유
- 빌드·테스트의 실제 실행 결과
- 남은 작업, 알려진 문제, 사용자 결정 필요 사항
- Claude 복귀 후 확인할 항목

## 3. 검토 원칙

기준 문서는 `AGENTS.md`, `CLAUDE.md`, `docs/GDD.md`, `docs/design/`이며 이 문서는 역할 분담을 보조한다. 최신 사용자 지시를 우선한다.

메모리 안전성·정확성 → 합의된 책임 분리 → 일정·구현 비용 → 성능·확장성 순으로 검토한다. 검토 의견을 확정된 설계로 취급하지 않는다. 실제 결함, 개선 제안, 아직 확인하지 않은 추측을 구분한다.

작성자 접미사와 헝가리안 정리는 기본 모드에서는 직접 수정하지 않고 필요한 사항을 기록한다. 기계적인 이름 정리만으로 원래 작성자의 구현 기여를 AI 작성으로 바꾸지 않는다.

## 4. 현재 작업: 사용자 World 구현

기준: `docs/design/world.md`. 현재 조회 시점에 World 구현 파일은 없으며, `tests/WorldTest_C.cpp`와 조건부 CMake 등록은 존재한다. 이번 작업에서는 빌드·테스트를 실행하지 않았다.

합의된 동작:

- `Entity` 하나로 플레이어·적·드랍을 표현하고 256개 고정 슬롯에 저장한다.
- 외부 참조는 인덱스와 세대 번호를 가진 `Handle`로 유지한다. 세대 0은 무효다.
- 용량 초과 시 `std::runtime_error`를 던진다. 용량 초과 처리 방식과 고정 용량 보장은 별개다. 무효 핸들 반환도 고정 용량을 유지할 수 있으나, 현재 합의는 throw다.
- `Destroy`는 예약만 하고, Flush 전에는 `Get`과 `ForEachAlive`에 계속 나타난다. 중복 예약은 무시한다.
- `FlushRemovals`에서 실제 해제와 세대 증가를 수행한다.

사용자 구현 순서:

1. `src/core/Handle.h`: 필드, 기본 무효 상태, `IsNull`, 동등 비교.
2. `src/core/Entity.h`: `EntityType`, `Entity`, 기존 `Body_C.h` 연결.
3. `src/core/World.h`: 공개 인터페이스, 내부 Slot·컨테이너, `ForEachAlive` 템플릿 본문.
4. `src/core/World.cpp`: 생성자 → Create → Get 두 버전 → Destroy → FlushRemovals → GetAliveCount.

처음에는 접미사 없는 파일로 작성해도 된다. `_U` 정리는 Claude 또는 명시적으로 위임받은 담당자가 수행한다. 테스트가 사용하는 공개 필드명은 world.md 인터페이스와 맞춘다. 구현 도중 함수별로 Codex 리뷰를 받아도 된다.

## 5. World 구현 시 확인할 점

- `reserve(256)`은 저장 공간만 확보한다. 슬롯 원소 256개는 `resize(256)` 또는 크기 지정 생성으로 만든다. 이후 슬롯 컨테이너 크기를 변경하지 않는다.
- 슬롯을 수정할 때 값 복사와 참조를 구분한다. 복사본을 바꿔도 원본은 바뀌지 않는다.
- `Get`은 인덱스 범위를 먼저 검사하고 생존·세대를 확인한다. const 버전도 필요하다.
- 삭제 대기와 빈 인덱스 목록도 미리 공간을 확보하여 통상 생성·삭제 중 재할당을 피한다.
- `ForEachAlive` 템플릿 본문은 헤더에서 보이게 둔다. 인라인 여부와 성능은 최적화 설정·호출 내용에 따라 달라진다.
- 순회 중 Destroy 예약은 가능하다. Flush를 순회 콜백에서 호출하지 않는다. 순회 중 Create는 메모리 주소가 안정적이어도 새 엔티티가 같은 순회에 포함될지 슬롯 위치에 따라 달라진다.
- 삭제 예약 후 접근 가능하다는 것은 모든 시스템이 같은 논리 상태를 본다는 뜻은 아니다. 사망 중복 처리와 후속 AI·공격은 별도 상태 검사로 방지한다.
- Flush 후 이전 포인터는 슬롯 메모리가 남아 있어도 이전 엔티티 참조로 사용하지 않는다. 장기 참조는 핸들을 유지한다.
- 32비트 세대 증가가 반복되면 언젠가 순환한다. MVP에서는 후순위로 두되 보장이 무한한 것은 아니다.

## 7. 인수인계 기록

### 2026-11-17 — 보조 역할 확정

- 첨부 인수인계 내용과 실제 World 설계·CMake 등록·파일 목록을 조회했다.
- 생성 파일: `docs/gpt_support.md`만.
- 소스 변경, World 구현, 빌드·테스트 실행, 커밋은 수행하지 않았다.
- 다음: 사용자가 Handle부터 직접 구현하고 Codex에 단계별 리뷰 요청.

### 2026-11-17 — 사용자 학습 피드백: World 의사코드의 설명 공백

- 사용자 의견: 의사코드만 보고 C++로 구현하려니 빈 부분이 많고 수수께끼를 푸는 느낌이다. 현재 설계대로 진행하되 Claude에게 피드백을 남기도록 요청했다.
- 구체적 사례: `idx = freeList.pop_back()`은 C++로 그대로 옮길 수 없다. `std::vector::pop_back()`은 값을 반환하지 않으므로 `back()`으로 값을 읽고 별도로 제거해야 한다.
- `Create(initial)`에서 initial의 의미·매개변수 타입, 반환할 Handle과 함수 반환형, 슬롯 원본 수정에 필요한 참조가 의사코드만으로는 충분히 드러나지 않는다.
- Claude 후속 권고: 설계 자체는 유지하고, 함수마다 입력·출력·사전 준비 타입과 의사코드에서 생략한 C++ API 차이를 짧게 덧붙인다. 완성 코드를 먼저 제공하지 말고 사용자가 작성할 수 있도록 한 단계씩 설명한다.
- 현재 사용자 코드: `void Create()` 안에 빈 목록 검사와 throw까지 작성. 검사는 방향이 맞으며 `<stdexcept>`가 필요하다. 다음 보조는 함수 입력·반환형 이해와 빈 번호 읽기/제거부터 진행한다.
- 이 기록만 수정했으며 소스 변경과 빌드·테스트는 수행하지 않았다.

### 2026-11-17 — Claude에게 전달: 의사코드 기반 구현 진행 결과

> 아래 내용이 앞선 Create 초기 단계 기록보다 최신이다. 사용자는 **2장 인터페이스 예시를 보지 않고 3장 의사코드만 보며 직접 구현**했고, Codex가 채팅에서 단계별 문법 설명과 리뷰를 제공했다. 아래는 채팅에 제시한 코드와 사용자 보고 기준이며 실제 파일의 최종 상태나 빌드 성공을 확인한 기록이 아니다.

진행한 범위:

- `Entity`는 아직 빈 구조체인 임시 상태다. `Slot`에는 Entity, 세대 1, 생존 여부, 삭제 예약 여부를 두었다.
- `Handle`에 인덱스·세대 필드와 기본 생성자(0, 0), 두 값을 받는 생성자를 직접 작성했다.
- World 생성자: 슬롯 256개 resize, 빈 번호·삭제 대기 목록 reserve, 빈 번호 255부터 0까지 등록.
- Create: 용량 초과 검사 → 빈 번호 읽기와 제거 → 초기 Entity 복사 → 생존·예약 상태 설정 → 인덱스와 세대로 Handle 반환.
- Get: 범위를 먼저 검사하고 생존·세대가 맞으면 슬롯 안 Entity 주소 반환. 사용하지 않는 Entity 복사본은 제거하도록 안내했다.
- Destroy: 유효성 검사, 중복 예약 무시, 예약 표시와 대기 목록 추가.
- FlushRemovals: 슬롯을 복사하던 코드를 참조(`Slot&`)로 변경하도록 안내했고 사용자가 적용했다고 보고했다. 생존 해제·예약 해제·세대 증가·Entity 초기화·빈 번호 반납 후 대기 목록 clear.
- ForEachAlive: 함수 템플릿과 콜백을 이해하고, 살아 있는 슬롯마다 `fnvisit(Handle{idx, slots[idx].gen}, slots[idx].value)` 호출까지 작성했다. 테스트와 맞도록 함수 이름의 대소문자를 `ForEachAlive`로 맞추도록 안내했다.

아직 남은 범위:

- `GetAliveCount() const`, const World용 `Get(Handle) const`, Handle의 `IsNull()`과 동등 비교. 이 항목들은 2장 인터페이스에는 있으나 3장 의사코드에는 빠져 있다.
- Entity의 실제 필드(EntityType, Body, HP), `kCapacity` 등 공개 인터페이스와 테스트 요구사항 대조.
- `Create(const Entity&)` 형태, `std::` 표기, 정수 변환 경고, 명명 규칙·작성자 접미사, 헤더/cpp 분리 정리. 사용자는 명명과 std:: 정리를 뒤로 미루고 핵심 동작부터 작성했다.
- 전체 구현의 실제 파일 확인과 Debug/ASan 빌드, World 스펙 테스트 실행. **현재 완료·통과로 취급하지 않는다.**

학습 과정에서 설명한 내용:

- `back()`은 마지막 값 조회, `pop_back()`은 제거이며 반환값이 없다.
- 값 복사와 원본 참조의 차이. `Slot&`는 원본의 별명이고 주소를 저장하는 `Slot*`와 구분한다.
- C++ 범위 기반 for의 `:` 문법.
- 콜백은 전달받은 작업을 호출하는 방식이며 `Fn`은 작업 타입, `fnvisit`은 매개변수 이름이다. 함수 템플릿은 World 클래스 안에서 해당 함수 바로 위에 붙이며 본문은 헤더에 둔다.

Claude에게 요청:

1. 현재 사용자 구현을 먼저 읽고 위 진행 기록과 대조해 리뷰한다.
2. **3장 의사코드만으로 전체 인터페이스가 완성되는 것처럼 안내하지 않는다.** 누락 기능마다 목적·입력·출력·의사코드와 필요한 C++ 문법을 짧게 보완한다.
3. 완성 구현을 먼저 제공하기보다 사용자가 다음 부분을 직접 작성할 수 있도록 단계별로 돕는다. Codex도 처음부터 2장과 3장의 범위 차이를 설명하지 못했으므로 안내 공백은 양쪽에서 보완한다.
4. 남은 기능 작성 후 파일·명명·테스트 연결을 정리하고 빌드·테스트로 검증한다. 구현 기여는 사용자 작성으로 보존한다.

이번 갱신은 `docs/gpt_support.md`만 수정했다. 소스 수정, 빌드·테스트, 커밋은 수행하지 않았다.

### 2026-11-17 — 1일차 중단 지점 / Claude 파일 분리 인계 (최신)

사용자는 보충된 world.md를 따라 구현을 진행했고, 이제 Claude에게 파일 분리와 정리를 맡긴 뒤 쉬었다 이어가기로 했다. 여기서 '물리 분리'는 Physics 변경이 아니라 한 파일에 작성한 타입과 구현을 헤더/cpp로 나누는 의미다.

최신 첨부 `d6d948ba-66e7-4d3d-b3e1-86b06fd59726/붙여넣은 텍스트.txt`를 정적으로 검토했다. 앞선 기록의 미구현 목록보다 이 기록을 우선한다.

- EntityType과 Entity의 종류·Body·HP 필드를 작성했다.
- Handle 생성자를 없애고 필드 기본값, `IsNull() const`, 기본 동등 비교를 작성했다.
- Create는 `const Entity&` 입력을 사용한다. Get 일반/const 버전, GetAliveCount, Destroy, FlushRemovals, ForEachAlive까지 본문을 작성했다.
- 공개 `static constexpr uint32_t kCapacity = 256`을 추가했고 resize/reserve와 ForEachAlive 조건에 적용했다.
- 핵심 알고리즘에 추가적인 명백한 오류는 이번 정적 검토에서 발견하지 못했다. **실제 컴파일·테스트 통과는 미확인**이다.

Claude가 이어서 처리할 사항:

1. 최신 사용자 소스를 확인하고 Handle, Entity, World 헤더와 World.cpp로 분리한다. ForEachAlive 템플릿 본문은 헤더에 유지하고, Slot은 World 내부 private 타입으로 둘 수 있다. 헤더 중복 포함 방지와 include 경로를 정리한다.
2. Handle의 `idx/gen`을 테스트가 사용하는 `uIndex/uGen`과 일치시키고 관련 접근부를 함께 정리한다. `std::uint32_t` 등 명명·표기 정리를 수행한다.
3. 아직 Get 두 버전에 `h.idx >= 256`이 남아 있으므로 kCapacity로 바꾼다. 생성자 반복문은 signed int 하향 순회를 유지하되 `static_cast<int>(kCapacity) - 1`로 시작하고, push_back 시 `static_cast<std::uint32_t>(i)`로 명시 변환하여 정수 타입 의도를 분명히 한다.
4. 파일 작성자 표기는 사용자 구현 기여를 보존한다. 기계적인 파일 분리·명명 정리는 사용자 코드의 저작 기여를 AI 구현으로 바꾸지 않는다. 실질적인 AI 구현을 추가하면 합의된 혼합 작성 주석 규칙을 적용한다.
5. CMake와 WorldTest include를 최종 파일명에 맞추고 Debug/ASan 빌드 및 World 스펙 테스트를 실행한다. 실제 경고·오류·테스트 결과를 사용자에게 보고한다.
6. 이후 사용자 실행 확인과 사용자 직접 커밋으로 이번 작업을 마무리한다. World와 게임 연결, SpatialQuery, Chaser, HP·피격 연결은 후속 작업으로 남아 있다.

이번 Codex 작업은 이 문서 갱신과 첨부 정적 리뷰뿐이다. 소스 수정, 빌드·테스트, 커밋은 수행하지 않았다. 사용자가 돌아와 요청하기 전까지 후속 구현을 진행하지 않는다.

### 2026-11-19 — Stats 사용자 구현 리뷰 / Claude 인계

사용자가 Stats 작성을 마치고 점검·보고를 요청했다. 실제 확인 파일은 `src/systems/Stats.h`, **`build/Stats.cpp`**다. 후자는 아직 src에 없으므로 통상 CMake 자동 등록 조건을 충족하지 않는다.

구현 내용: enum·스탯/보정 구조체, 정적 Calculate 선언, 참조 반환 GetField, Add/Mul 별도 합산, 기본값 복사 후 `(base + Add) * (1 + Mul)` 계산, 최종 0 하한 처리가 작성되어 있다. 사용자 요청으로 범위 for와 마지막 스탯 순회 블록의 C++ 예시를 Codex가 제공했으므로 구현은 사용자 주도이며 일부 AI 제공 코드가 포함됐다. 최종 작성자 표시는 해당 기여와 기존 규칙에 맞춰 정리한다.

검증: 원본 소스는 수정하지 않고 `build/codex-stats-check`에 검증 전용 CMake 프로젝트를 생성했다. 기존 `TestMain_C.cpp`, `StatsTest_C.cpp`와 현재 build/Stats.cpp를 직접 연결하여 **MSVC C++20, /W4, /permissive-, /utf-8, Debug ASan**으로 빌드했다. **Stats 테스트 7개·assertion 13개 모두 통과.** 이는 독립 검증이며 일반 Main/전체 테스트 연결 완료를 뜻하지 않는다.

발견 사항 / Claude 후속 작업:

1. **GetField 반환 위치 오류:** 마지막 `return tBlock.fMaxHp;`가 switch 안에 남아 있다. 각 case는 return하므로 이 줄은 도달 불가(C4702), 미등록 enum 값이면 함수 끝까지 반환 없이 도달한다(C4715). 마지막 return을 switch 닫는 중괄호 뒤, 함수 안으로 옮겨야 한다. 테스트는 정상 enum만 사용하여 이 문제가 있어도 통과했다.
2. **기본 공격 범위 불일치:** Stats.h의 `StatBlock::fAttackRange` 기본값이 0.0f다. 설계의 기본 범위 배율은 1.0f이므로 이를 복원하고, Calculate의 **tAdd와 tMul은 fAttackRange까지 명시적으로 0**으로 초기화해야 한다. 현재는 기본값을 0으로 둬 합계는 맞지만 기본 StatBlock의 범위가 0이 된다. 기존 테스트는 base의 범위를 1로 명시하므로 이 차이를 잡지 못한다.
3. `build/Stats.cpp`를 `src/systems/Stats.cpp`로 이동하고 CMake 재구성하여 Stats 구현 포함 ON을 확인한다. include·명명·작성자 표기를 정리하고 경고 없는 Debug/ASan 빌드 및 전체 테스트를 다시 실행한다.
4. 테스트 통과 후에도 아이템 보정 목록 생성과 최종 스탯의 Motor/Combat/최대 HP 연결은 별도 후속 작업이다. 현재 계산 함수 통과만으로 게임 연결 완료라고 보고하지 않는다.

이번 Codex 작업은 조회, build 아래 검증 생성물 작성·빌드·테스트, 이 문서 갱신이다. 사용자 소스/테스트 원본은 수정하지 않았고 커밋하지 않았다.

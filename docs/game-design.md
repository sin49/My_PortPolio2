# 기획서 v0.2 — 2D 룸 클리어 액션 (이름 미정)

> **문서 상태**: 프로토타입(v0.1, 2026-11-19) 기준 "지금까지 정한 것" + "확장 계획".
> 초기 기획은 `docs/GDD.md`(v0.1, 구현 계획 중심). 이 문서는 **플레이 경험과 설계 의도** 중심으로 다시 정리한 것.
> 작성 방식: 결정과 이유는 개발자, 정리·서식은 AI(Claude). 수치는 실제 데이터 표(`src/data/`)에서 가져옴.

## 1. 한 줄 소개
**짧은 방 하나하나가 작은 결투인 2D 근접 액션.** 적의 예고 동작을 읽고 피하거나 대시로 빠져나간 뒤 반격하고, 방을 깰 때마다 얻는 아이템으로 조금씩 강해진다.

## 2. 플레이 경험 목표
| 목표 | 플레이어가 느껴야 하는 것 | 지금 쓰는 장치 |
|---|---|---|
| **읽고 반응하는 전투** | "맞은 건 내가 못 읽어서" | 근접 적 예고 0.4초 + 공격 범위 표시, 원거리 적 발사 전 깜빡임 |
| **반격 타이밍** | 적이 공격한 직후가 내 차례 | 적 공격 뒤 회복 0.6초 (그 동안 멈춤) |
| **기동성** | 빠르고 가볍게 움직이는 손맛 | 달리기·대시·코요테 타임·점프 버퍼 |
| **눈에 보이는 성장** | 방을 깰수록 강해지는 게 숫자로 보임 | 클리어 보상 아이템, 스택 수와 효과를 HUD에 표시 |
| **맞는 감각** | 맞았다는 걸 몸으로 앎 | 피격 무적 0.6초 + 히트스톱 + 화면 흔들림 |

## 3. 핵심 루프
```
방 입장 → 문 잠김 → 적 등장
   → 예고 읽기 → 회피(대시·점프) → 반격
   → 전멸 → 문 열림 + 아이템 1개 → 다음 방
   (HP 0 → 처음부터 / 보스 처치 → 승리)
```
- 한 방은 짧게(수십 초). 실패해도 다시 하기 부담이 적게.
- 회복약은 **HP를 많이 잃었을수록 잘 나옴**: 드랍 확률 = 5% + 35% × 잃은 HP 비율 (HP 가득이면 0%). 위기일 때 숨 돌릴 틈.

## 4. 조작과 이동 감각
| 키 | 동작 | 설계 의도 |
|---|---|---|
| ← → | 이동 | 출발 0.15초, 멈출 때 살짝 미끄러짐 (딱 멈추는 것보다 무게감) |
| Z | 점프, 길게 = 더 높이 | 높이를 손으로 조절. 코요테 0.1초·점프 버퍼 0.12초로 억울한 실패 방지 |
| X | 공격 | 콤보 없이 한 종류. 읽고 때리는 리듬에 집중 |
| Shift 짧게 | 대시 (약 4칸, 시작 0.1초 무적) | 예고를 읽었을 때의 탈출 수단. 게이지 절반 소모 |
| Shift 길게 | 달리기 (1.8배, 점프 높이 1.32배) | 기동성. 게이지 5초분 |

- **대시와 달리기를 한 키로**: 짧게 누르면 대시, 0.18초 넘게 누르면 달리기. AI는 "누르는 순간 대시"(반응 빠름)를 제안했지만, 키 하나로 두 동작을 쓰는 원래 의도가 더 중요해서 **0.18초 지연을 감수**.
- 게이지 공유: 대시를 남발하면 달리기도 못 함 → 회피 수단을 아껴 쓰게.

## 5. 전투
### 플레이어
- 공격력 10, 최대 HP 100. 근접 히트박스는 몸 앞 사각형, 한 번 휘두를 때 같은 적은 한 번만.
- 맞으면: 넉백 + 0.6초 무적(깜빡임) + 히트스톱 4틱(약 0.067초) + 화면 흔들림.
  - 무적이 없을 때는 겹친 적 여러 마리에게 한꺼번에 맞아 억울했음 → 무적 추가.
  - **경직(조작 불가)은 넣지 않음**: 맞는 느낌은 강해지지만 조작감을 해침. 맞은 직후에도 바로 피할 수 있어야 함.
  - 빨간 테두리 연출은 보류 (화면이 과해짐).

### 적 (예고 → 공격 → 회복 리듬이 공통)
| 적 | 역할 | 수치 | 설계 의도 |
|---|---|---|---|
| **근접 (작음/중간/큼)** | 기본 압박 | HP 10/20/30 = 플레이어 공격 1/2/3대, 속도 140, 예고 0.4초, 회복 0.6초 | 크기 = 맞아야 죽는 횟수 → 머리 위 점으로 남은 타수 표시. 작은 적을 가장 많이 배치 |
| **원거리** | 자리 강요 | HP 20, 거리 220~380 유지, 예고 0.7초, 쉬는 시간 2.4초, 탄 속도 320 | 근접 적과 같이 나와서 "가까이 갈지 피할지" 선택을 만듦 |
| **보스** | 패턴 읽기 시험 | HP 100(10대), 조준 3연사(24° 부채꼴) ↔ 8방향 원형탄 번갈아, 쉬는 시간 2.0 → HP 50% 이하 1.3초 | 두 패턴은 피하는 법이 다름(옆으로 / 틈 사이로). 2페이즈는 새 패턴 대신 템포만 빠르게 |

- **발판 위 적은 떨어지지 않음**: 플레이해 보니 적이 바로 뛰어내려 발판이 의미가 없었음 → 발판 끝에서 멈추게. 이제 위쪽 적을 잡으려면 플레이어가 올라가야 함 (넉백으로 떨어뜨리는 건 가능).

## 6. 아이템과 성장
| 아이템 | 효과 (스택마다) | 비고 |
|---|---|---|
| Heart | 최대 HP +20 | |
| Whetstone | 공격력 +5 | 작은 적 2타 → 1타 등, 체감이 큼 |
| Feather | 이동 속도 +12% | |
| Long Blade | 공격 범위 +25% | |
| Potion | 즉시 HP 30 회복 | 인벤토리에 안 남음, 적 처치 때 확률 드랍 |

- 방 클리어 보상 = 위 4종 중 무작위 1개. 같은 아이템을 또 먹으면 스택으로 쌓임.
- **스탯은 덮어쓰지 않음**: 기본값 + 보정값 목록으로 매번 다시 계산 → 아이템을 잃거나 버프가 끝나도 꼬이지 않음.

## 7. 레벨 구성
| 방 | 크기(칸) | 구성 | 의도 |
|---|---|---|---|
| 튜토리얼 | 70×22 | 조작 힌트 6개 + 허수아비 1 | 이동 → 점프 → 높이 점프 → 대시 → 달리기 → 공격 순서로 한 번씩 써 보게 |
| 방 1 | 56×22 | 발판 13개, 적 8 | 위로 올라가는 발판 + 위쪽에도 적 → 수직 이동을 쓰게 |
| 방 2 | 64×26 | 발판 18개, 적 11 (원거리 4) | 원거리 적이 높은 곳에서 견제 → 경로 선택 |
| 보스 | 50×22 | 발판 3개 | 넓은 바닥 + 피할 때 쓰는 발판 |

- 미니맵 + 방 진행 점 + 남은 적 수 표시. 방이 작아져서(플레이 피드백) 한 화면에 가깝게.

## 8. 플레이 테스트로 바꾼 것 (결정 기록)
| 날짜 | 관찰 | 결정 |
|---|---|---|
| 11/17 | 이동이 느리고 점프가 낮음 | 이동 260 → 340, 점프 속도 760 → 880 |
| 11/17 | 멈출 때 딱 멈춰서 딱딱함 | 살짝 미끄러지는 관성 추가 |
| 11/19 | 맵이 너무 넓음 | 방 크기 축소, 위로 가는 발판 추가 |
| 11/19 | 적이 발판에서 바로 뛰어내림 | 발판 끝에서 멈춤 |
| 11/19 | 맞는 느낌이 약함 | 무적 + 히트스톱 + 흔들림 (경직은 제외) |
| 11/19 | 보스·원거리가 너무 자주 공격 | 원거리 예고 0.5 → 0.7, 쉬는 시간 1.4 → 2.4 / 보스 HP 300 → 100, 예고·쉬는 시간 늘림 |
| 11/19 | 근접 공격이 갑작스러움 | 예고 동안 공격 범위 표시 |

모든 수치는 데이터 표에 있어서 코드 수정 없이 조정 가능.

## 9. 지금의 한계 (기획 관점)
- **보는 재미가 없음**: 그래픽·애니메이션·이펙트 리소스가 없어 색 사각형. 첫인상이 약함 (강사 피드백: "결과물은 특별한 게 없다").
- **성장이 단조로움**: 아이템이 전부 "숫자 +". 선택도 없고(무작위 1개), 조합 재미도 없음.
- **목표·동기가 약함**: 방 3개 + 보스로 끝. 다시 할 이유(무작위성, 해금, 기록)가 없음.
- **전투 깊이**: 공격 1종, 적 3종. 적 조합으로 만드는 상황이 적음.
- **난이도 검증이 감**: 사망 위치, 클리어 시간 같은 데이터 없이 느낌으로 조정.
- **적끼리 겹침**: 근접 적이 한 자리에 몰려 겹쳐 보임 (성능에도 영향).

## 10. 확장 계획
> 원칙: **한 프로젝트에서 프로그래밍 포폴과 기획 포폴을 같이** 만든다. 기능 하나마다 "기획 의도 → 구현 → 플레이 검증" 기록을 남긴다.
> 리소스와 기획은 확장의 필수 조건. 프로그래밍만 더 하면 결과물 인상은 크게 안 바뀜.

### 1단계 — 보이는 것 (리소스 + 손맛)
| 할 일 | 기획 포인트 | 프로그래밍 포인트 |
|---|---|---|
| 아트 방향 확정 (다크 판타지 도트, 사용자 레퍼런스 기준) | 톤·색·캐릭터 실루엣 가이드 1장 | — |
| 플레이어·적 스프라이트 + 애니메이션 (대기/이동/예고/공격/피격/사망) | **예고 동작이 한눈에 읽히는지**가 기준 | Render만 교체 (상태는 이미 FSM에 있음), 애니메이션 상태 매핑 |
| 타일셋·배경 | 발판이 "올라갈 수 있는 곳"으로 보이게 | 타일맵 렌더 |
| 타격·피격 이펙트, 효과음 파일 | 손맛 | 파티클·사운드 데이터화 |
| 적 겹침 해결 (적끼리 밀어내기) | 근접 적이 "무리"로 보이게 | 진영별 검색 분리 + 분리 조향, 성능 재측정 |

- 리소스 제작: 무료·유료 에셋 + 생성 도구로 초안 → 손 보정. 출처와 라이선스는 표로 기록.

### 2단계 — 깊이 (기획 핵심)
| 할 일 | 기획 포인트 |
|---|---|
| **보상 선택** (3개 중 1개) | 무작위 1개 → 선택. 빌드 방향을 플레이어가 정함 |
| **아이템 시너지 / 단계 효과** (3·5스택 특수 효과, 처치·피격 때 발동) | "숫자 +"에서 "플레이 방식이 바뀌는" 아이템으로 |
| **적 추가** (비행 적, 방패 적 등) | 기존 적과 조합했을 때 새 상황이 생기는지 기준으로 선정 |
| **방 조합** (층마다 방 배치를 무작위로 + 모든 방에 갈 수 있는지 검증) | 다시 할 이유. 난이도 곡선(방 순서별 적 구성) 설계 |
| 공격 확장 (강공격 또는 2단 콤보 중 하나) | 읽고 때리는 리듬을 해치지 않는 선에서 |

### 3단계 — 검증 (기획을 숫자로)
- 플레이 기록 도구: 사망 위치·원인, 방별 클리어 시간, 받은 피해, 아이템 선택을 CSV로 저장 (이번 성능 측정 도구와 같은 방식).
- 외부 플레이 테스트 3~5명 → "의도한 난이도 vs 실제" 비교 → 조정 기록.
- 결과물: 기획 포폴의 "테스트 결과" 장, 프로그래밍 포폴의 "테스트 자동화" 장.

### 4단계 — 선택 (여유가 있을 때)
- 2인 협동 → 대전(PvP). 지금 구조(의도 분리, 고정 타임스텝, 핸들)가 네트워크 전제에 맞음.
- 플레이 영상 30초, 웹 빌드(브라우저에서 바로 실행).

### 단계별 포폴 산출물
| 단계 | 프로그래밍 포폴 | 기획 포폴 |
|---|---|---|
| 1 | 렌더 교체 구조, 적 겹침 해결 + 성능 재측정 | 아트 방향 가이드, 예고 동작 가독성 기준 |
| 2 | 아이템 이벤트 구조, 방 생성 + 도달 검증 | 보상·시너지 설계, 적 조합표, 난이도 곡선 |
| 3 | 플레이 기록 도구 | 플레이 테스트 결과와 조정 기록 |

## 11. 결정이 필요한 것 (개발자)
1. 게임 이름과 세계관 한 줄 (아트 방향과 같이)
2. 1단계 아트: 직접 그림 / 에셋 구매 / 생성+보정 중 무엇으로
3. 2단계 순서: 보상 선택 → 시너지 → 적 추가 → 방 조합 (제안 순서) 그대로 갈지
4. 공격 확장을 할지, 한 종류로 유지할지

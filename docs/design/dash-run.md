# 대시 / 달리기 분리 (Hades 2 방식) — 설계·구현 기록

> 상태: **구현 완료 (2026-11-17)**. 사용자 요청: 맵을 넓게 + 기동성 ↑ (Spatial Hash가 의미 있게).
> 사용자 사양: Shift 짧게 = 대시(짧고 빠른 전진 + 짧은 무적), 길게 = 달리기(무적 없음). 둘 다 게이지. 대시 50%.
> 장거리는 달리기가 유리. 대시는 수평만. 달리면서 점프하면 더 높이. 대시 방향 = 누르는 방향, 없으면 마지막 방향.
> 방향키 없이 Shift만 누르면 달리기 아님(게이지 소모 X). 게이지 회복 빠르게, 달리기 소모 적게.

## 11/17 실행 후 사용자 수정 (최신)
- **짧게(0.18초 안에) 눌렀다 뗀 순간 대시 / 0.18초 넘게 누르고 있으면 달리기** (대시 없이 바로 달리기). 아래 AI 판단은 폐기.
  - 대시가 뗄 때 나가므로 최대 0.18초 늦게 나감 → 사용자가 이 방식을 원함. 판정 시간은 `fDashTapTime`으로 조정
  - 두 고정 틱 사이에 눌렀다 뗀 아주 짧은 탭도 `bDashPressed` 래치로 잡음
- 이동 속도 260 → **340** (달리기 612). 정지 미끄러짐이 1칸을 넘지 않게 `fGroundStopTime` 0.19 → 0.17
- 플레이어 머리 위 게이지 바 (쓰는 중이거나 덜 찼을 때만, 흰 눈금 = 대시 가능선)

## (폐기) AI 판단 (사용자 사양과 다른 점 1개)
- "짧게 눌렀다 뗐는지"를 **뗄 때 판정하면 대시가 늦게 나감**(입력 지연). 그래서 Hades 2처럼 **누른 순간 바로 대시**,
  대시가 끝난 뒤에도 누르고 있으면 **달리기로 이어짐**. 결과적으로 "짧게 = 대시만 / 길게 = 대시 + 달리기".
  → 대시 없이 바로 달리고 싶으면? 지금은 불가. 필요하면 "누른 채 방향키를 나중에 누르면 달리기만"으로 조정 가능.

## 구현 요약
- `MoveIntent.bDashPressed` (래치) 추가. Input이 Shift 누른 순간 기록.
- `DashState`: `bRunning`, `fDashTimer`, `fInvulnTimer`, `iDashDir`, `IsDashing()`.
- 대시 중: 수평 속도 고정, `vVel.fY = 0`, `Body.bNoGravity = true` (Physics가 중력 건너뜀). 대시 중 점프 = 대시 끊고 점프.
- 대시가 끝나면 대시 속도 → 달리기/걷기 속도로 감속하며 이어짐 (뚝 끊기지 않게).
- Render: 대시 중 = 밝은 하늘색, 달리기 = 하늘색.
- 테스트 12개 (달리기 6, 대시 6). 전체 51개 통과.

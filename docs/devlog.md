# 개발 로그

AI 협업 기록. 날짜별로 "한 일 / AI가 제안한 것 / 사용자가 수정·거절한 것과 이유"를 짧게 남김.

## 2026-11-16 (월)
### 한 일
- CMake + raylib 5.5 + doctest 환경 세팅, 고정 타임스텝(1/60s) 루프, Debug `/W4` + ASan 빌드 확인
- 플레이어 이동/점프/타일 충돌 의사코드 초안 (`docs/design/player-movement.md`)

### AI가 제안한 것
- 누적기를 `core/FixedTimestep.h`로 분리해서 raylib 없이 테스트 → 샘플 테스트 대상으로 사용
- ASan을 `GAME_ASAN` 옵션으로 만들고, 라이브러리가 없으면 구성 단계에서 바로 안내 (링크 에러 LNK1104 대신)
- 타일 크기 후보: 32px 40x22칸 vs 16px
- 이전 프로젝트 `Player.cs` 분석: 점프 버퍼 타이머를 가변 dt에서 감소, 코요테 시간 제한 없음, 가변 점프가 코루틴 의존 → 고정 틱 + 타이머로 재설계

### 사용자가 수정·거절한 것 (이유)
- 타일: 32px 40x22칸 선택 + **위·아래 검은 프레임 8px**을 직접 추가함 (720/32 = 22.5칸의 0.5칸이 어색해 보이지 않게)
- 코요테 타임·점프 버퍼·가변 점프 전부 MVP에 포함 (이전 프로젝트에서 구현해 본 경험 있음)

### 구현 (의사코드 합의 후)
- 플레이어 이동/점프/타일 충돌 구현: `PlayerMotor`(의도 → 속도, 점프 보조), `Physics`(중력·축 분리 충돌), `Tilemap`, `Render`(8px 프레임), `Game`
- raylib 비의존 로직을 `GameLogic` 라이브러리로 분리 → 게임·테스트가 공유. 테스트 17개 통과

## 2026-11-17 (화)
### 사용자가 수정·거절한 것 (이유)
- 게임 이름(가칭 Necro Rooms) → 일단 `Main`으로 변경. 프로젝트·실행 파일·창 제목 모두
- 공격 방식: 근접 유지 (원거리는 World 핸들 풀이 먼저 필요해서 MVP 일정에 불리하다는 AI 의견에 동의)
- 이동 키 A/D → 방향키. 멈출 때 딱 멈추던 것 → 살짝 미끄러지는 관성 추가 (가속/감속 분리, 지상 정지 거리 약 24px)
- 플레이어 크기는 유지, 대신 나중에 맵을 키우고 카메라를 고민하기로
- 대시 추가 (GDD에 없던 범위): 처음엔 "게이지, 다 쓰면 절반 회복까지 금지"만 정함 → AI가 의사코드 쓰는 중에
  "무적 없음, 누르는 동안 빨리 달리기"로 정의를 좁힘
- 키: Z 점프 / X 공격 / Shift 대시. 공중 대시 허용. 공격 중 이동 안 막음(나중에 대시 공격 만들기 쉽게). 공격 버퍼 추가
- **AI 제안 수정:** AI가 `MoveIntent`를 `Intent`로 합치자고 했는데, 사용자가 "책임 분리가 망가진다"고 우려
  → `MoveIntent`(Motor만 읽음) / `AttackIntent`(Combat만 읽음)로 분리. 사용자 지적이 맞았음

### 한 일
- 대시(게이지·탈진), 근접 공격(Ready/Active/Recover + 버퍼), facing 구현. 테스트 28개 통과
- 근접 히트박스는 엔티티가 아니라 상태 값 → 생성/삭제 없음. 단 맞은 적 목록은 핸들로 저장해야 함(World 이후)

### 오후: 조작감 조정 + World 설계 합의
- 출발 가속을 "최고 속도까지 걸리는 시간"으로 조정: 걷기 0.15초, 대시 0.08초(대시는 더 빨리 붙게) — 사용자 요청
- World 결정 9개 확정 (`docs/design/world.md`). 사용자 판단: 용량 초과는 크기를 늘리지 않고 throw
  (늘리면 고정 슬롯의 메모리 의미가 사라짐), 나중에 대기 큐. CLAUDE.md에 "복구 안 하는 치명적 오류만 throw" 조항 추가
- 사용자 질문 → AI 설명: ForEachAlive 성능(템플릿 람다는 인라인되어 for문과 같음), 삭제 예약 A/B 장단점(Unity Destroy와 같은 A)
- World 스펙 테스트 10개(AI 작성) — 임시 구현으로 테스트 자체가 맞는지 확인 후 임시 구현은 삭제
- **사용자 규칙 추가:** AI가 작성한 `.cpp`는 `_C` 접미사 (포폴에서 AI/사용자 작성 범위 구분). CLAUDE.md 명명 규칙 수정
- 프로젝트 설명서 `docs/code-guide.md` (빌드·조작·수치 조정 위치·파일 작성자 표)

### 저녁: 명명 규칙 확정 (사용자 결정, 세부는 AI 위임)
- 변수명 **헝가리안** (`fSpeed`, `bGrounded`, `tBody`, 클래스 멤버 `m_`). 세부 표는 AI가 정해서 CLAUDE.md에 기록
- 파일명: AI만 = `_C`, 사용자만 = `_U`, 섞이면 접미사 없음 + `// work: claude` / `// work: user` 구역 주석. 헤더도 적용
- **명명 처리는 AI 담당**: 사용자는 신경 안 쓰고 작성 → AI가 리뷰 때 변수명·파일명·주석을 맞춤
- 기존 AI 코드 전부 헤더 `_C` + 헝가리안으로 재작성 (로직 변경 없음, 테스트 29개 그대로 통과)
- World 스펙의 공개 필드는 헝가리안으로 명시 (`uIndex`, `uGen`, `eType`, `tBody`, `fHp`) — 테스트가 이 이름을 쓰기 때문

### 작업 방식 합의
- World는 사용자가 결정 → AI가 의사코드·파일 위치 정리 → 사용자가 구현 → AI가 리뷰
- 모르는 코드·개념은 사용자가 ChatGPT에 질문 (사용량 부담 분산)

### 결정 (사용자 → AI 위임 포함)
- `PlayerMotor` 분리는 사용자가 AI 판단에 맡김 → Physics를 적과 공용으로 유지하려고 분리, GDD 7장 표 수정
- 플레이어 저장 위치: (B) Game이 임시 소유 (World는 사용자가 직접 작성 예정)
- 플레이어 크기 24x40: "해보고 문제 있으면 수정"

- World 핸들 풀 (사용자 작성) → 플레이어 이전
